## Approved design and implementation

One main plugin entry runs per player; no global entry, database, account, hosted service, model registry, or transcript subsystem.

| Proposed source | Responsibility and narrow interface |
|---|---|
| `src/main.ts` | Compose one per-player `Session`; handle validated bridge messages, IINA events, media/track epochs, pause/resume, observer/timer cleanup. No linguistic parsing here. |
| `src/iina-host.ts` | Small wrapper for actual release APIs: current media/track/time, `@sub/<id>` reads, overlay/sidebar, native visibility ownership, Keychain calls. Test code can replace these functions with a fake host. No invented IINA methods. |
| `src/subtitles.ts` | `parseSubtitles`, `cueAt`, `contextForCue`. Operates on text and milliseconds; no IINA or DOM access. |
| `src/conversation.ts` | `SelectionSnapshot`, immutable `ContextSnapshot`, request/turn ownership, prompt and Chat Completions message construction, manual retry rules. Completed, incomplete, and failed assistant turns are distinct. |
| `src/stream.ts` | ASCII line framing from the helper, base64/UTF-8 decoding, request IDs, response/error limits. The native helper parses provider SSE; pure parser tests use fragmented records. The stdout hook only queues bytes; a plugin timer drains them and performs host/UI work. |
| `src/credentials.ts` | Only Keychain storage and status. Calls verified lowercase names; saved key is read only for an actual request and never returned to UI state. |
| `ui/overlay.html`, `ui/overlay.ts`, `ui/overlay.css` | One plain-text source cue with `white-space: pre-wrap`; browser `Selection` capture; compact Explain action. Defer cue repaint while a selection/action is active, without pausing. Only the cue/action area is clickable. |
| `ui/sidebar.html`, `ui/sidebar.ts`, `ui/sidebar.css` | One dark explanation/chat view and a compact settings view. Use `textContent` for subtitles/model text; plain-text assistant output is acceptable for MVP. Keep phrase pinned. Enter sends and Shift+Enter inserts a line break, respecting composition. Explicit Close/Resume and Stop are separate. |
| `native/stream-helper.swift` | One short lived per-request executable using Foundation/URLSession, private request/control FIFOs, ASCII records on stdout, and a non-secret cancel marker. Product transport and owner checks are implemented and exercised against the local mock endpoint. |

**Concrete data contracts.** `SelectionSnapshot` contains `{mediaEpoch, sourceTrackId, cueIndex, cueStartMs, cueEndMs, cueText, rangeStartUtf16, rangeEndUtf16, exactText}`. `ContextSnapshot` freezes that selection, up to three preceding and three following source cues, bounded overlapping secondary cues, and both language settings. The secondary-context choice is applied when the snapshot is made. `RequestOwner` contains `{mediaEpoch, conversationId, requestId}`; every chunk, completion, close, and retry checks it. The bounded helper request JSON contains the validated endpoint, Chat Completions body, and an optional key kept only in privileged memory and the FIFO. The UI bridge accepts fixed message names and validated data shapes, never an arbitrary file path or privileged command from a WebView.

**Selection and conversation flow.** Overlay text is a single text node, so UTF-16 selection offsets map directly to the displayed cue even across visual wraps or actual line breaks. Mouse selection alone never pauses or requests. Natural cue advancement freezes a pending selection, including an active drag; explicit user seek clears an uninvoked selection. An existing conversation retains its captured context across either event. Explain captures the existing cue/range/context, consumes the pending selection so a duplicate click cannot send twice, pauses the same player, opens the sidebar, validates settings, and starts one request. Follow-ups keep the original snapshot and only completed turns. A new Explain cancels/invalidates the old request and conversation. Stop marks any partial assistant text incomplete and stays paused. Close invalidates the request, hides the sidebar, and explicitly calls resume only for the same playable media generation, including if that media was paused before Explain. Ended/stopped or replaced media never resumes. Settings dismissal alone leaves the conversation paused.

**Native sidebar fallback.** Explicit Close/Resume is authoritative. For native dismissal, the sidebar WebView sends `visibilitychange`; privileged code treats `hidden` with the same live media and a still-visible window as Close/Resume. Hidden while minimized is deferred and cleared if `visible` returns. Back, outside click, tab switch, and fullscreen Back resumed in installed IINA; minimizing and opening/closing Settings did not. This supports the fallback on those paths. A dedicated app-focus switch and simultaneous two-window conversation dismissal remain untested. `core.window.sidebar` cannot identify a plugin tab in this release.

**Native subtitle ownership.** On a readable external source track, remember the current primary visibility and set only `sub-visibility=false`; leave source track selected and `secondary-sub-visibility`, secondary track, and positioning untouched. Restore only the value this instance owns on supported media change, window close, overlay failure, and in-plugin Disable Overlay; do not overwrite a user change made while active. Disable Overlay cancels active work, invalidates late results, closes the conversation under the established resume rules, and restores owned native state in that window, including during an active stream. Rebuild the source timeline on selected track/media changes. Each player instance owns its own cache, selection, conversation, helper, and resume token. Raw Preferences disable has the approved limitation: no teardown callback; a helper can run until total timeout, native primary subtitles can remain hidden, and playback can remain paused. Manual recovery is **Subtitles → Show Subtitles** and **Playback → Resume**. Immediate cancellation or prevention of provider billing cannot be promised. No IINA fork is an MVP prerequisite.

## Subtitle and provider contracts

**Guaranteed input:** local media with user-supplied external UTF-8 SRT or WebVTT text subtitles, including full-length files within approved size/cue limits, UTF-8 BOM, CRLF, multiline cues, and WebVTT identifiers. Parse cue times and plain text; ignore supported formatting tags and WebVTT NOTE/STYLE/REGION blocks without rendering their HTML. Reject malformed/ambiguous files with a visible explanation and keep native playback usable. ASS/SSA, bitmap subtitles, embedded tracks, remote subtitle files, and extraction are outside this release. Complete commercial tracks may be user-supplied runtime inputs; never commit or distribute them as fixtures. The secondary track is optional, but if selected and external SRT/VTT it is parsed independently. If secondary text is unavailable, omit it rather than reusing a stale line. Native English visibility does not depend on `includeSecondarySubtitleContext`.

Read `@sub/<selected external id>` once per track/media generation, validate size and association, and index the entire in-memory cue timeline. This is how three following cues exist before playback reaches them. Use effective media time and source/secondary delays to find active cues; use `sub-start`, track ID, and the exact displayed text to reject mismatches, particularly repeated lines and seeks. The 1-second delay probe showed that `sub-start` remains the file timestamp while display timing shifts. `sub-speed` and secondary delay have automated fixture coverage; native checks remain outstanding. Stable chronological order with file-order tie breaks handles overlapping cues; an ambiguous selection across multiple simultaneously displayed cues yields no actionable overlay while native subtitles remain available. Secondary context is every cue whose effective interval overlaps the selected source cue, with a size bound that errors rather than silently omits required text.

The privileged side constructs `POST <canonical-base-path>/chat/completions` with exact model, ordered messages, `stream: true`, JSON content type, and Bearer auth only when configured. Source subtitles are structured, untrusted data separated from instructions; initial instructions always require Natural meaning and Literal meaning plus concise breakdown/grammar. Follow-ups do not force those headings. No tools, remote media, automatic retry, silent provider switch, or silent context shortening. Store non-secret endpoint/model/languages/secondary option in IINA preferences. Associate Keychain items with the canonical endpoint, preserve path prefixes, and require deliberate credential setup on a new endpoint. Changing provider settings cancels the active request and resets its conversation; turning secondary context off does the same so old automatic translation context cannot be resent. Settings save alone performs no provider call.

**Transport boundary, tested in a package and product.** The Swift helper creates a private mode-0700 request directory and mode-0600 request/control FIFOs; `utils.exec` receives only the executable path and private directory path. Privileged plugin code reads the current key from IINA Keychain and writes it with bounded request JSON through the request FIFO. The helper accepts HTTPS or explicit loopback HTTP, rejects URL credentials and cross-origin or method-changing redirects, and follows only same-origin 307/308 redirects. URLSession drops Authorization during a redirect, so the helper restores that header only after the same-origin check. It parses fragmented SSE/UTF-8 bytes, emits bounded ASCII records to stdout, and cancels its URLSession task on Stop. The installed product delivered incremental chunks, Stop/in-plugin Disable Overlay cancelled a request, and the controlled helper tests covered auth, rate limits, outage, malformed SSE, timeouts, redirects, and rejection of an untrusted TLS certificate. A positive trusted HTTPS request remains untested. **IINA invokes the `utils.exec` stdout hook on a background file-handle queue.** The production hook only queues bytes; a plugin timer performs all IINA/WebView/file work. This tested approach does not eliminate every host-level concurrency risk. A raw Preferences disable removes the timer but does not signal Stop, so an active request can continue until its total timeout. Normal IINA Quit left no helper or FIFO and the mock server observed disconnect, but exact cancellation latency on host exit is unproved. A separate helper's direct Keychain read failed, so IINA privileged code must read the key. Neither key nor prompt goes in arguments, ordinary files, stdout diagnostics, or logs. See the milestone report for the crash observed with the discarded callback design and the corrected retest.

**Implemented limits:** 8 MiB per subtitle file, 50,000 cues, 4,000 characters per cue/selection, 2,000 characters per follow-up, 20 turns, 128 KiB request JSON, 64 KiB response text, 64 KiB SSE event, 20-second first-byte, 30-second idle, and 120-second total request timeout. Over-limit inputs fail with a visible reason; interrupted responses are incomplete when partial text exists. No required cue or completed turn is silently removed. Boundary tests do not yet cover every limit in installed IINA.

## Permissions, dependencies, and license

Plugin identifier: `io.github.hanifcarroll.iina-language-learning` (stable and distinct from references). Newly written code is MIT licensed. No GPL-licensed IINA/SubTandem implementation or unlicensed DeepHear code was copied. Runtime uses macOS Foundation/URLSession and IINA only. The pinned development dependencies are TypeScript, Bun types, and happy-dom; Bun's bundler builds the JavaScript. Reading `@sub/<id>` and setting `sub-visibility` are supported without a broader filesystem permission, but executing the helper requires it. Do not request `show-osd` or `show-alert`. The helper's direct network access is outside IINA `http` domain enforcement, so settings and installation documentation must say this plainly. `allowedDomains` is empty; no wildcard is needed because `iina.http` is not the provider transport. The owner approved this wider native-helper trust boundary for the MVP.

**Current state:** The approved product implementation is committed locally. No IINA fork, custom build, or upstream API change is an MVP prerequisite. Native dismissal worked on tested Back, outside-click, tab-switch, and fullscreen paths, so an explicit-Close/Resume-only fallback is not proposed. The current product evidence and remaining checks are in [ACCEPTANCE_REPORT.md](ACCEPTANCE_REPORT.md). Raw Preferences disable can leave the helper running to its total timeout, native primary subtitles hidden, and playback paused, and cannot guarantee prevention of provider billing. Release and distribution remain outside this local implementation work.
