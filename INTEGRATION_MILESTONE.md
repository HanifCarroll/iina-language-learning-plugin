# Installed-IINA integration milestone

**Date and target:** 2026-09-23; macOS 27.0 arm64; installed IINA 1.5.0-beta2 build 172 with bundled mpv 0.41.0. This is a synthetic integration harness, not the finished language-learning plugin. It uses a generated grey video, two short synthetic SRT files, a local mock server, and a generated disposable Keychain value. No real provider, credentials, commercial subtitle fixture, or billable request was used.

## What was built

- `native/stream-helper.swift` is the packaged Swift URLSession SSE executable. It receives a private directory path, creates mode-0600 request/control FIFOs there, accepts bounded JSON through the request FIFO, and sends bounded base64-encoded delta records on stdout. It applies endpoint, redirect, response-size, and timeout checks and removes its FIFO directory on normal termination.
- `integration/` is a disposable per-window IINA plugin that exercises a selectable DOM overlay, native secondary subtitles, sidebar visibility, Keychain read/write, and the helper. It only auto-loads the synthetic tracks for a video path ending in `/clip.mp4`. The sidebar exposes local mock modes and an in-plugin Disable Overlay control.
- `scripts/build-integration.sh` builds the folder under ignored `dist/`. IINA's bundled `iina-plugin pack dist/org.hanif.phase0.integration.iinaplugin` produced `org.hanif.phase0.integration.iinaplugin-0.1.0.iinaplgz`; `unzip -t` passed. The archive was installed into an isolated application-support profile and run by the installed IINA. The normal plugin directory was not changed.
- `tests/test_stream_helper.py`, `tests/mock_server.py`, and `tests/fixtures/` provide the local checks. No reference implementation was copied. The `.references/` clones remain ignored and read-only.

The first raw-disable experiment crashed IINA twice while an **older harness** called `iina.file.write()` directly from `utils.exec`'s stdout hook. The installed-release crash report located the fault in `JavascriptAPI.parsePath` called from `JavascriptAPIFile.write`, reached through the `JavascriptAPIUtils.exec` file-handle callback. IINA invokes that hook off the main queue. The corrected harness only queues bytes in the hook; a plugin timer handles host APIs and UI updates. Raw disable on the corrected package did not reproduce the crash. This is a concrete restriction for the product adapter, not proof that all concurrent JavaScriptCore teardown races are impossible.

The test plugin saved and read a generated mock key with the installed runtime's exact `utils.keychainWrite` and `utils.keychainRead` names. The key travelled to the helper through a FIFO, never in `utils.exec` arguments. The local server logged only an authorization boolean. The fixture Keychain item was deleted after testing, and a lookup confirmed it was absent.

### Native sidebar dismissal

The sidebar WebView's `visibilitychange` signal combined with `core.window.visible` worked on the tested paths. Native Back, a click outside the sidebar, a switch to another plugin tab, and fullscreen Back each produced `hidden` with a visible player window; the harness closed the conversation and resumed eligible playback. Explicit **Close/Resume** also resumed the same playable media; a close at media end did not restart it. Minimize produced `hidden` while the player window was not visible and did **not** close the conversation. Opening and closing IINA Settings did not cause a close or resume. These results support the native-dismissal approach; an explicit-Close/Resume-only fallback is **not proposed** on current evidence. App focus switching and simultaneous two-window dismissal still need tests before product acceptance.

## Remaining limits and next scope

- The integration harness does not implement SRT/VTT parsing, context assembly, prompt construction, follow-ups, provider settings, full product request ownership, or complete turn-state UI. The full-length user-supplied external UTF-8 SRT/VTT path remains in scope within the proposed size/cue limits. Complete commercial tracks must not be committed or distributed as fixtures; they are valid user-supplied runtime inputs.
- Raw Preferences disable offers no plugin teardown event in this IINA release. An active helper can continue to total timeout; native primary may remain hidden, and a paused conversation may remain paused. Users should use the in-plugin Disable Overlay control for normal shutdown. Manual recovery after raw disable is **Subtitles → Show Subtitles**, then **Playback → Resume** if needed. No IINA fork, custom build, or upstream API change is required for the MVP.
- The helper permits any validated HTTPS endpoint by design, while this milestone exercised only loopback HTTP. Product settings must validate the configured endpoint and bind its Keychain item to that canonical endpoint. The native helper's direct network access is outside IINA's `allowedDomains` enforcement and needs clear permission documentation.
- A forced host crash can leave FIFO filesystem nodes. No secret is written to an ordinary file, but abnormal cleanup is best effort. Keychain overwrite was verified in Phase 0; same-item write failure and provider-specific error shapes remain untested.
- The repository has no `.git` directory, so no commit or Git diff was possible. No push, release, provider call, or modification to the normal IINA plugin directory was made. The generated Keychain item and temporary normal preference enable flag were removed; IINA and the mock server were stopped.
